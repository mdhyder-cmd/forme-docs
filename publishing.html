FORME / 0.5.6

Give the handbook a home.

Publish these static documentation files with GitHub Pages.

Publish with no build tools

  1. Extract FORME-0.5.6-github-pages-docs.zip on your computer.
  2. On GitHub, create a repository named forme-docs under mdhyder-cmd. Use a public repository if you are on GitHub Free. Add a README when creating it.
  3. Use Add file Upload files. Upload the extracted index.html, guide HTML files, assets/, and the other documentation files at the repository root. Upload the contents, not another enclosing folder.
  4. Commit to main. An empty .nojekyll file is included; if your computer hides it, create a root file named .nojekyll in GitHub.
  5. Open Settings Pages Build and deployment. Set Source: Deploy from a branch, Branch: main, and Folder: /(root). Save.
  6. Wait for the Pages deployment to succeed. Return to Settings Pages and select Visit site.
Expected address after you publish

https://mdhyder-cmd.github.io/forme-docs/
This address is prepared in the theme metadata. It is not activated by extracting the ZIP.

What belongs in the public repository

Only the documentation files from the docs ZIP. Keep the paid theme ZIP, private theme source, product imports, test orders, credentials, and seller-only files out of it. GitHub Pages is for this static handbook; run the Shopify storefront and any paid delivery/checkout through appropriate services.

If you choose another account or repository

The documentation uses relative links, so it can work under another project URL. Update the documentation/support URLs in the theme’s config/settings_schema.json before distributing a differently branded package, and update the expected address on this page and in the README.

Updating the handbook

Edit and commit the HTML or replace the documentation files in main. Pages republishes from that branch. Review the deployment status under Actions. If the site is missing, check the selected branch/folder and verify that index.html sits directly at that publishing root.
